# 排错方法论第一铁律（troubleshoot-first-rule）

面向智能体的排错方法：**普遍性问题通常已有现成解**，无需先行原创分析、反复尝试或另行开展技术研究。

由 **天工创新坊** 开发维护，许可 **CC BY 4.0**。

## 有什么用处？

- 出现报错、故障或异常时，给出第一步该做什么：检索报错原文
- 报错文案明确的问题（如"XX 不能被加载""停止代码 0x..."），命中现成解即直接执行

## 为什么要用？

有实战对照：处理 VB6 启动失败时，自行编写工具、抓包、查询注册表，耗时 8 小时未解决；改为先检索报错原文后，10 分钟找到公开的现成解法并修复。普遍性问题通常已有他人遇到并公开解答，原创分析相当于重复实现已有方案。

## 如何用？

1. 检索报错原文（中英文并行检索），关键词加"解决" / "solution" / "fix"
2. 优先查阅官方文档、社区高赞答案、Stack Overflow、知乎、博客园
3. 命中前 3 个现成解即直接执行，无需另建方案
4. 未检索到现成解，再进入深入分析（抓包、注册表、专用工具）

## 不推荐的做法

- 拿到报错即编写诊断脚本、抓取进程信息、查询注册表——此类手段宜留到最后
- 忽略"先找现成解"的提示，继续原创分析
- 仅检索中文不检索英文（西方技术栈问题的英文资料通常更为完整）

## 关联
